# 术语表

快速参考：本方法论中使用的术语及其定义。

| 术语 | 定义 | 常见误解 |
|---|---|---|
| 调度员 | 用户的 Claude Code 主会话，负责任务拆解、Agent 派发、验收汇总 | 不是独立进程，就是你跟 Claude Code 的对话 |
| Agent | Claude Code Agent tool 生成的子会话，执行特定子任务 | 不是长期运行的服务，一轮结束后上下文就丢了 |
| 前置分流器 | 任务到达时用 3 个 yes/no 问题判断走极简/框架/探针模式 | 不是智能路由，就是 3 个判断题 |
| 探针 Agent | 专门深挖用户真实需求的 Agent，只问不答，1 轮完成 | 不是需求分析师，不做方案设计 |
| 极简模式 | 定位→执行→交付，≤3 轮，禁止派 Agent/写复盘/读 memory | 不是偷工减料，是简单任务的正确处理方式 |
| 框架模式 | 完整 5 步流程：任务拆解→调度执行→验收闭环→全局审视→验证交付复盘 | 不是所有任务都要走这个模式 |
| 批评家 | 强制对抗审查角色，按致命/严重/轻微分级输出问题 | 不是挑刺，是质量兜底。找不到问题→引入第二批评家 |
| 验收者 | 从原始需求出发逐项评估的角色，必须代入服务对象视角 | 不是最后才出场的 QA，每轮都要给评分 |
| 信号驱动 | 根据执行过程中出现的信号按需引入角色，不是预设 pipeline | 不是固定流程，是动态响应 |
| 任务地图 | 调度员输出的子任务拆解：子任务、依赖关系、调度批次、角色、验收标准 | 不是项目计划，是本轮执行的调度依据 |
| 调度声明 | 每轮调度前输出：并行组/串行链/输入产出标准 | 不是状态报告，是执行前的确认 |
| 经验→决策检查点 | 读 memory 经验后必须转化为"本次必须检查：[具体动作]"，否则视为未读 | 不是把经验贴上去，是要变成具体的检查动作 |
| 复盘纪要 | 任务结束后的结构化自评估：效率/质量/协作/版本演进/改进建议 | 不是流水账，每项要有具体数字或案例 |
| 红线 | 触发暂停的 6 个条件（如批评家找不到问题、验收者连续两轮相同批评） | 不是警告，是必须暂停处理 |
| 反模式 | 15 条禁止行为（如跳过分流器、假分工、读了经验不转化） | 不是建议，是做了就算违规 |
| [已验证]/[待确认]/[推测] | 竞品对比中每条结论的置信度标注 | 不是免责声明的替代品，是逐条自检 |
