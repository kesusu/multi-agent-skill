# 自学习 — "学"和"查"分离的 AI 辅助学习

> 核心思想：自己出题自己答 = 盲区。用不同角色分别负责"学"和"查"。

## 这是什么

用多 Agent 协作框架驱动自主学习。AI 阅读教材 → 提炼知识点 → 做笔记 → 出题 → 用笔记模拟答题 → 诊断薄弱点 → 迭代笔记。

关键创新：**"学"的角色和"查"的角色由不同 Agent 扮演**，避免"自己出题自己答"的盲区。

**需要**：[Claude Code](https://claude.ai/code) + [multi-agent skill](../../README.md)。没有 Claude Code 的话，手动在不同对话中扮演不同角色也能达到类似效果（见下方"没有 Claude Code 怎么用"）。

## 工作流

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│ 学教材   │ ──→ │ 做笔记   │ ──→ │ 出题     │ ──→ │ 模拟答题 │ ──→ │ 诊断     │
│ (学习者) │     │ (学习者) │     │ (出题者) │     │ (答题者) │     │ (诊断者) │
└─────────┘     └─────────┘     └─────────┘     └─────────┘     └─────────┘
      ↑                                                              │
      └──────────────────── 迭代笔记 ────────────────────────────────┘
```

### 角色分离：为什么 AI 也需要

| 角色 | 职责 | 为什么不能合并 |
|:---|:---|:---|
| 学习者 | 阅读教材、提炼知识点、做笔记 | — |
| 出题者 | 根据教材出模拟题 | AI 出题时倾向于生成"训练数据中常见的题型"，冷门/难的知识点天然被忽略——因为生成概率低 |
| 答题者 | **仅用笔记**模拟闭卷答题 | 如果用教材答，无法暴露笔记缺陷；如果用同一个上下文窗口，刚写的笔记内容会被"记住"而非"查找" |
| 诊断者 | 分析答题记录，找笔记薄弱点 | 同一上下文窗口里，AI 刚写了笔记，紧接着诊断时会倾向于认为笔记是完整（上下文偏差）——缺失的内容不在当前对话记忆里 |

**一句话**：AI 的"自问自答盲区"不是心理问题，是上下文窗口偏差——同一个对话里，刚写的内容会影响后续判断。

## 实际案例：激光原理考试准备

用这个工作流为《激光原理》（周炳琨，第六版）准备考试资料。以下两个文件是核心产出，**建议先看**：

| 文件 | 内容 | 说明 |
|:---|:---|:---|
| [`sample_output/答题诊断报告.md`](sample_output/答题诊断报告.md) | 27 道题的逐题答题记录 | **最能说明"查"的价值**——展示了诊断者如何发现笔记缺陷 |
| [`sample_output/考试预判.md`](sample_output/考试预判.md) | 题型概率预判 + 高频易错清单 | **最能说明"学"的价值**——展示了学习者如何主动分析而非被动记笔记 |

### "查"的价值：答题诊断报告

诊断报告不是简单地给出答案，而是模拟了"翻笔记找答案"的全过程：

```
### 第9题（阈值条件说法不正确）
- 查找路径：看到"阈值增益""g_t"→公式速查表G区→g_t=δ/l→...
- 答题耗时：15秒
- 置信度：高
- 笔记问题：笔记写g_t=δ/l（l=工作物质长度），参考答案写g_t=δ/L（L=腔长）
  → 这是笔记中最大的公式矛盾，需对照教材确认
```

完整报告覆盖 27 道题，每题都记录了查找路径、耗时、置信度。诊断结果：

| 发现类型 | 数量 | 例子 |
|:---|:---|:---|
| 公式矛盾 | 2 | 阈值增益 l vs L、纵模个数 +1 vs 不 +1 |
| 缺失内容 | 2 | He-Ne 增益介质为混合气体、激光器三基本组成 |
| 模糊内容 | 2 | 标准具插入公式、输出功率中 δ 的含义 |

**如果没有"查"的角色，这些缺陷在考试时才会暴露。**

### "学"的价值：考试预判

考试预判展示了"学"的角色如何主动分析而非被动记笔记：
- 4 个必考题型（概率 > 80%）+ 4 个高频题型（50-80%）
- 7 条高频易错清单（考前过一遍）
- 分值预估分布（三能级/高斯光束各 10-15 分，是最大分值来源）

### 开卷 vs 闭卷的关系

这个案例**同时包含**开卷和闭卷的准备：
- **闭卷模拟**：用闭卷版模拟题测试记忆，生成答题诊断报告（发现笔记缺陷）
- **开卷准备**：基于诊断结果迭代笔记、速查表、索引，确保开卷时 30 秒内能找到答案

诊断报告显示：27 道题中 24 道能在 30 秒内找到答案，3 道需要 > 1 分钟（需计算），0 道找不到。开卷可用性评分 9.5/10。

## 没有 Claude Code 怎么用

这个案例用 multi-agent skill 在 Claude Code 中自动调度角色。但角色分离的核心思想不依赖框架：

1. **学习阶段**：在一个对话中让 AI 学教材、做笔记
2. **出题阶段**：开一个**新对话**（清空上下文），让 AI 根据教材出题——新对话没有笔记的上下文，出题不会被笔记内容影响
3. **答题阶段**：再开一个**新对话**，只给它笔记文件（不给教材），让它模拟答题
4. **诊断阶段**：再开一个**新对话**，给它答题记录，让它找笔记缺陷

**关键**：每个角色在不同的对话中执行，避免上下文窗口偏差。多 Agent 框架只是自动化了这个过程。

## 适用场景

| 场景 | 怎么用 |
|:---|:---|
| 备考（开卷/闭卷） | 学教材 → 做速查表 → 出模拟题 → 用速查表模拟答题 → 诊断薄弱点 |
| 技术文档学习 | 读文档 → 做笔记 → 出概念测试题 → 用笔记答 → 诊断理解盲区 |
| 新领域入门 | 读综述/教材 → 做知识图谱 → 出判断题 → 用图谱答 → 诊断知识缺口 |

## 核心洞察

### 1. "学查分离"避免自问自答盲区

自己出题自己答，最大的问题不是"作弊"，而是**无意识地避开自己不会的东西**。AI 在生成题目时，倾向于生成训练数据中常见的题型——冷门/难的知识点天然被忽略，因为生成概率低。出题者和答题者必须在不同的上下文窗口中。

### 2. 诊断报告比模拟题更有价值

模拟题告诉你"答对了多少"（一个数字），诊断报告告诉你"笔记哪里有缺陷"（可操作的改进方向）。这个案例中，诊断报告发现了 6 个笔记缺陷——每一个都可以直接改进。

### 3. 公式必须标注来源

速查表中的每个公式都标注了教材章节和公式编号。这不是形式主义——诊断报告发现的 2 个公式矛盾（阈值增益 l vs L），正是因为有来源标注才能追溯到教材原文确认。

## 与 multi-agent skill 的关系

这个案例是 multi-agent skill 的一个验证场景，证明框架可以用于非代码任务。核心价值不在于代码文件，而在于**角色分离的设计模式**——它适用于任何需要"自我验证"的学习或工作场景。
