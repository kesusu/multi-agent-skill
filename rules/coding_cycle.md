# 编程执行循环

写代码任务的默认流程：

1. **定位**：找入口文件、调用链、相关测试和配置。复杂问题追到根因。
2. **判断**：说明最小可靠改动点。局部修补会埋雷时，提出结构性方案。
3. **修改**：只改相关文件，沿用项目风格。
4. **验证**：优先跑最小相关测试，再按风险扩大范围。
5. **收尾**：清理自己引入的无用代码，汇报改了什么、怎么验证。

## 失败处理

- 先读失败信息和相关代码再改。
- 连续 2 次失败：停下来重新定位根因，不要继续盲改。

## 卡住时

- 信息不够：继续读最相关的文件/日志/测试。
- 现象矛盾：构造最小复现。
- 改了又坏：回到调用链找共同根因。
- 连续两轮无进展：主动复盘当前知道什么、不知道什么。
